# 第一阶段交付状态

## 已在代码中实现并本地验证

- `DATABASE_URL` 存在时使用托管 PostgreSQL；未设置时沿用本地 SQLite。页面明确显示当前存储类型。
- 已有 SQLite 客户按标准化域名合并，并保留关联草稿；新背调与 CSV 导入也按域名去重。
- 客户库支持 CSV 导入、完整 JSON 备份与恢复；旧网站导出的 JSON 格式也可恢复。
- 本地 20 项自动测试通过；服务启动后的 `/health` 和已授权 `/api/status` 返回正常；网页脚本语法通过。

## 尚未验收的线上环节

1. 在当前 Render 网站导出旧客户 JSON 并留存。当前云环境没有该网站的工作台连接码，无法代用户读取私有客户库。
2. 在 Render 建立并连接用户自己控制的持久化 PostgreSQL。没有 `DATABASE_URL` 或 Render 管理权限，不能验证真实数据库连接。价格应以 Render 控制台购买时显示为准；本云环境访问 Render 定价文档被代理返回 403。
3. 如需 Codex CLI 登录在重新部署后保留，为服务配置持久磁盘并设置 `TRADESCOUT_DATA_DIR` 为挂载目录。业务数据库不会保存 Codex 登录文件。
4. 旧站备份确认可用后才将新版本部署到 `tradescout-windows` 分支对应的线上服务；部署后恢复旧备份，核对客户和草稿数量，并再次导出备份验证。
5. 用户在 OpenAI 官方设备授权页面完成 Codex 登录，并在网站点击“测试 Codex 实际连接”。此前只有模拟测试，不能宣称订阅模型已在线可用。

后续第二阶段是逐项证据审批、人工计分和可信客户队列，须在第一阶段的真实数据持久化及 Codex 调用验收后上线。
