# Sean 的外贸主动开发：逐步可复制提示词

根据用户提供的 17 页《外贸主动开发客户工作流》整理。原教程是**美国服装 DTC + Apollo + Mac 本机程序 + 自动发送**的示例；以下提示词改为 Sean 已确认的**阿联酋／沙特／南非区域批发商与进口商 + 家居／厨房／收纳／礼品 + 公开来源 + 网页系统 + 个人 Gmail 草稿、人工发送**。详细业务要求见 [USER_REQUIREMENTS.md](USER_REQUIREMENTS.md)。

使用方法：按 01→11 的顺序操作。方括号填写当前批次的信息，未知项可留空并让我标为“待确认”。每一步可单独复制给我；如果是在同一会话继续，可省略重复的背景说明。步骤 05、06、09、10、11 是**建设或维护系统**的提示词，步骤 01–04、07–08 是**实际开发客户**的提示词。

## 01 用真实客户做种子画像

如果暂时没有已成交客户，可用你亲自确认的理想买家官网作为候选样本；不能把“理想样本”说成成交客户。

```text
我在义乌提供多品类找货、验货、拼柜／集运服务，目标市场是阿联酋、沙特、南非，核心品类为家居、厨房、收纳、礼品。我主要想找区域批发商、进口商及合适的多品类分销商。

请以[已成交客户官网或我确认的理想买家官网]为种子，为我建立可用于找公司的买家画像。只使用可公开核实的网页资料，分析它的国家和服务地区、批发／进口业务模式、产品品类、客户渠道、公司规模线索、采购与补货线索、公开联系方式，以及哪些特征值得复制、哪些只是个性化特征不该硬套。

把结论分成“有来源的公开事实”“合理推断”“需我补充的私有交易经验”三栏。给出搜索关键词（包括可用的英文和当地常见叫法）、排除关键词、候选公司筛选条件和来源链接。暂不找联系人或邮箱；没有可靠的中国采购证据时写“未知”，不要推断。
```

## 02 只建立公司候选池

原 PDF 的 Apollo 公司搜索可作为可选渠道；用户当前确认的基础渠道是公开网页和 CSV，不预设 Apollo 账号或付费额度。

```text
沿用我已确认的画像，先为[国家：阿联酋／沙特／南非]的[品类：家居／厨房／收纳／礼品]寻找[数量，例如 30]家区域批发商、进口商或多品类分销商候选。优先查公开官网、行业目录和可访问的公开商业资料；如果我提供 CSV，也一起去重处理。

这一轮只收集公司：公司名、官网、国家／服务区域、主要品类、为何可能适合我的一句话理由、发现来源网址及日期。按官网主域名去重，保留不同发现来源。排除明显零售个人店、纯制造工厂、营销代理和与品类无关的公司。

不要购买、解锁或猜测联系人邮箱，不要把搜索结果称为已核实客户。请把无法打开网页、来源不足或公司身份存疑的条目标为“待核实”，并报告搜索数量、去重后数量和下一轮建议核查的数量。
```

## 03 公开背调与证据清单

```text
请对[粘贴公司名单及官网，或指定客户库筛选条件]逐家做公开背调。核实它是否真实在经营目标品类、是否有批发／进口／分销业务、面向哪些市场、最近公开业务活动，以及是否有直接可信的中国采购线索。不要把网页能打开、目录标记 active 或商品存在当成充分证据。

每家公司列出：官网、业务模式、相关品类、批发或进口证据、近期活动、可能的采购需求、风险、每项主张的来源网址与可核对摘录，并给出“建议我审核／继续核实／排除”的建议。来源打不开或只能找到间接线索时明确写未知。中国采购证据缺失时保留候选，但此项不加分。

所有评分证据先标为“待我审核”；只有我逐项通过后才计分。请不要在这一阶段拿联系人或生成开发信。
```

## 04 我批准公司后再核实工作邮箱

```text
下面是我已人工批准的公司及官网：[粘贴清单]。现在请按每家公司最多一个优先联系人或公开工作邮箱，查找适合采购对接的渠道。对区域批发／进口企业优先找采购、进口、品类、商品或运营负责人；没有可靠个人联系人时可以考虑官网公开的采购／业务工作邮箱。

只接受官网或其他公开可核实的工作邮箱，记录邮箱、公司域名、来源网址、核实日期、联系人姓名和职位（若确有公开证据）。不要猜邮箱、不要找个人邮箱或手机号、不要通过姓名加域名推算地址。任何公司、域名或任职错配都标为“未解决”。

输出“可供我确认／待补充／无有效邮箱”三组；无有效邮箱的公司保留在客户库，但暂不生成可发送的草稿。不要写信或发送。
```

## 05 建立或检查网页工作台

如果已经有项目，优先检查现有实现和数据，不能把这段当作重建并清空数据库的命令。

```text
请按我的外贸系统需求检查现有项目[仓库或目录]和现有网站[网址]，先报告哪些功能已在代码实现、哪些通过本地测试、哪些已在线上真实验收。然后建设或改进我的私人网页工作台，让我能直接从浏览器完成客户搜索、CSV 导入、去重、来源核实、逐项证据审批、客户管理、邮件草稿审核、跟进和看板。

我的业务是义乌多品类找货、验货、拼柜／集运；市场为阿联酋、沙特、南非，品类为家居、厨房、收纳、礼品。数据必须长期保存、可备份恢复。使用我授权的 Codex CLI 与订阅额度；不能未经同意改成按 API Key 计费。已有客户、草稿和审批记录不能因重建或部署丢失。

请先给出可验收的小阶段并逐阶段实施。每阶段提供真实可打开的网址和完成检查，清楚说明仍需要我本人做的官方账号授权。不要仅给项目 ZIP、工作区路径或要求我每天运行 Windows 脚本。
```

## 06 连接我的个人 Gmail

原 PDF 使用 SMTP／IMAP 与应用专用密码；我的已确认方案是个人 Gmail 的 Google OAuth 草稿与同步。

```text
请在我的网页工作台中接入个人 @gmail.com 账号，用 Google 官方 OAuth 由我本人授权。先核实 Google 当前对个人 Gmail、草稿创建、已发邮件读取、回复读取、授权有效期和公开部署的要求，再选择能长期使用的权限与连接方式。给我按当前页面可操作的授权步骤；不要让我把密码、验证码、Cookie 或令牌发到聊天里。

先实现“创建 Gmail 草稿”和“读取已发／回复状态”。连接测试只验证授权和必要接口，不发送测试邮件。网页只显示授权状态与错误，不返回令牌明文。CRM 保存相关邮件主题、时间、状态、Gmail 会话链接及我手写的摘要；原文留在 Gmail。

验收时区分：OAuth 已授权、草稿成功创建、我实际在 Gmail 发送、系统同步到真实发件、系统识别回复。授权失败或同步中断要明确显示，不能误判为客户未回复。暂不自动给客户发信。
```

## 07 为批准的公司写英文首封与跟进草稿

原 PDF 生成 5 封自动发送序列；我当前确认的是首封和第 4／11 天两次未回复跟进，全部人工发送。

```text
请只对我已经批准证据、并且有可核实公开工作邮箱的公司[名单或客户库筛选条件]写英文邮件草稿：一封首封开发信，以及首封实际发送且未回复时才会用到的第 4 天、第 11 天跟进草稿。

我的真实服务仅为义乌多品类找货、验货、拼柜／集运。每封邮件只引用该公司经我批准的具体公开事实；没有足够证据就用诚实的问题切入。不得编造客户案例、产品认证、MOQ、价格、交期或效果。文字简短、自然、有一个易回答的问题。可按原项目默认值检查英文标题不超过 6 词、正文不超过 50 词；这些字数不是我不可更改的硬要求。

请给每封提供英文标题、英文正文、中文理解对照、使用了哪些已批准事实及其来源。全部保存为待我审核的草稿；不要批准、排期或发送。第 4／11 天从真实发件日计算，若已有回复则不生成新的跟进草稿。
```

## 08 我逐封审核并给修改意见

```text
请给我展示[客户／草稿批次]的英文主题和正文、中文理解对照、事实来源，以及每封草稿的审核状态。我会逐封留下意见。请根据我的意见修改英文邮件，同时更新中文对照，并说明改动；原有留言与修改记录保留。

有未处理意见的草稿不能标为“审核通过”。我修改了已通过邮件的内容时，必须重新审核。批量通过若提供，只能改变审核状态，不能触发发送；跳过仍有未处理意见的草稿。

请在隔离测试数据里验证：保存留言后退回待审、未处理留言拦截通过、修改后重新审核、批量操作不会发送真实邮件。最终报告每封的状态、未处理意见数和实际发送数。
```

## 09 把跟进规则做成工作台待办和 Gmail 草稿

原 PDF 的“开始发送”会由系统自动发信，与我已经确认的人工发送方式冲突，因此此步改为提醒和准备草稿。

```text
请实现我的人工发送跟进流程：只有 Gmail 同步到真实首封发件消息后，才开始计算第 4 天和第 11 天的到期待办。到期而且确认没有收到回复时，在工作台提醒我，并生成可审阅的 Gmail 跟进草稿；由我本人在 Gmail 决定是否发送。

任何收到的回复都暂停后续跟进提醒和草稿生成；真人回复应终止既定跟进，自动回复则标记待我判断，未经我决定不恢复。同步失败时显示“无法确认回复状态”，不要继续自动准备发信动作。跟进任务要能推迟、完成或关闭，重复运行不得重复生成相同草稿。

每天向我自己的邮箱汇总一封到期待办摘要。向我的邮箱发送内部摘要可以自动执行；绝不自动给潜在客户发送开发信。请用测试数据验证真实发件前不启动计时、回复后停止、同步中断时安全暂停、重复任务不重复生成。
```

## 10 同步回复、退信并更新销售阶段

```text
请把 Gmail 的相关已发邮件、回复及退信事件与正确的客户、收件人和会话关联。首次连接时不要把全部历史邮件当作本轮新回复；同步要记录游标或等效位置，重复读取不重复建事件。

区分真人回复、自动回复、退信和无关邮件。任何回复都先暂停后续提醒；真人回复终止既定跟进；退信标记该邮箱不可用并提醒我核实；自动回复单独显示、等我决定是否恢复跟进，不能冒充真人询盘。识别结果不确定时标为待我确认，不猜测。

在客户时间线显示事件与 Gmail 会话链接，让我继续手工记录回复、询价、报价、样品、订单及输单原因。CRM 只存主题、时间、状态、链接和我写的摘要，邮件正文仍留在 Gmail。请验证同一会话、不同联系人、历史邮件和重复同步的情况，并分别报告“同步成功”与“真实有回复”的事实。
```

## 11 稳定运行、数据恢复与真实验收

原 PDF 的 Mac LaunchAgent、本机端口和 SQLite 守护配置不适合我当前选择的 Render 网页。

```text
请检查我的 Render 网页及其仓库配置，让工作台、Gmail 同步和每天的内部待办摘要可靠运行。客户、证据审批、联系人、邮件元数据和跟进记录要保存在持久化数据库中，并有可恢复备份。服务器上的 Codex 登录如需跨部署保留，要单独安排安全持久化。

在任何可能清除旧数据的部署前，先导出旧网站客户资料并验证恢复路径。列出确实需要购买的服务和 Render 当前实际价格供我审核；不要凭猜测报价或自动购买。账号授权、付款和需要我登录的控制台步骤请给出最少而准确的操作说明。

逐项真实验收：网址可打开、私人访问控制有效、一次真实 Codex 模型请求成功、公司去重、证据审批后才计分、重启后数据仍在、备份可恢复、Gmail 草稿创建、我实际发送后状态同步、回复停止提醒、内部摘要按时到达。测试完成后区分“代码完成”“本地测试通过”“线上已验证”及“尚待我授权”。
```

## 下一批客户的续做提示词

```text
请继续使用我现有的外贸客户系统，先读取当前客户库、证据审批、Gmail 同步状态和到期待办，不要重置数据。按我的已确认范围处理新一批[国家／品类／来源]公司：找公司候选 → 公开背调与来源清单 → 等我逐项批准证据 → 核实公开工作邮箱 → 给已批准且有邮箱的客户生成英文 Gmail 草稿 → 等我发送 → 同步真实发件和回复 → 第 4／11 天提醒。

任何未审核证据不得加分或写入个性化事实；找不到可靠邮箱就保留公司但不发信；收到回复立即停止后续提醒。结束时报告新增候选、已审核合格公司、有可核实邮箱公司、待审草稿、真实已发、收到回复、到期待办、同步错误，并附可追溯来源。不得把草稿数写成已发送数。
```

## 从 PDF 继承与调整的关键判断

- **保留**：用种子客户建立 ICP；先搜公司再核实联系人；公开背调和人工拍板；草稿、审核、发送、回复分别记状态；用真实结果验收。
- **改写**：美国服装 DTC → 三国多品类批发／进口；Apollo 付费解锁 → 优先公开工作邮箱；本机 Mac／SQLite → 网页与持久化数据库；SMTP 自动序列 → 个人 Gmail OAuth 草稿和人工发送；5 封序列 → 首封及第 4／11 天跟进。
- **不照搬的数字**：原案例的 99 家候选、35 家背调、10 家批准、9 个邮箱、45 封草稿是作者当时的结果，不能当成我的业绩、目标或系统验收数字。
